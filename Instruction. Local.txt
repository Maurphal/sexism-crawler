Καλή στιγμή να το δοκιμάσεις πριν κάνεις push — όλα τρέχουν τοπικά με πραγματικό internet access (δεν χρειάζεσαι GitHub Actions για τη δοκιμή, μόνο για το scheduled μέρος).

1
Ξεπακετάρισε και μπες στον φάκελο
Αποσυμπίεσε το sexism-crawler.zip και άνοιξε τερματικό μέσα στον φάκελο sexism-crawler/. Χρειάζεσαι Python 3.9 ή νεότερη εγκατεστημένη.
2
Εγκατέστησε τις εξαρτήσεις
Τρέξε: pip install -r requirements.txt (ή μέσα σε virtualenv: python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt). Εγκαθιστά requests, beautifulsoup4, PyYAML.
3
Τρέξε πρώτα τα unit tests
python tests/test_analyzer.py — δεν χρειάζεται internet, ελέγχει μόνο τη λογική ανίχνευσης πάνω σε έτοιμα κείμενα. Αν δεις 'Όλα τα tests πέρασαν', η βασική λογική δουλεύει σωστά στο περιβάλλον σου.
4
Βάλε 1-2 πραγματικές σελίδες στο sites.yaml
Άνοιξε config/sites.yaml και αντικατέστησε το placeholder με 1-2 πραγματικά URLs — ιδανικά δικές σου σελίδες ή κάτι δημόσιο που ξέρεις ότι επιτρέπει scraping, ώστε η πρώτη δοκιμή να είναι καθαρή.
5
Τρέξε την πραγματική σάρωση
python -m src.crawler — θα κάνει πραγματικά requests στις σελίδες σου (σεβόμενο robots.txt), θα τρέξει την ανάλυση, και θα γράψει το results/latest.json. Στο τερματικό θα δεις πόσα ευρήματα βρέθηκαν ανά σελίδα.
6
Έλεγξε το JSON αποτέλεσμα
Άνοιξε το results/latest.json σε editor ή κάνε cat results/latest.json — δες αν τα findings που εμφανίζονται έχουν νόημα (σωστές λέξεις, λογικές προτάσεις). Αν μια σελίδα αποτύχει, το πεδίο error θα σου πει γιατί (π.χ. robots.txt απαγόρευση, timeout, HTTP 404).
7
Παρήγαγε και άνοιξε την HTML αναφορά
python -m src.report δημιουργεί το docs/index.html. Άνοιξέ το απευθείας στον browser σου (διπλό κλικ ή file:///.../docs/index.html) για να δεις πώς θα δείχνει η τελική αναφορά στο GitHub Pages.
8
(Προαιρετικό) Προσομοίωσε ολόκληρο το GitHub Actions workflow
Αν θες να ελέγξεις και το ίδιο το .yml πριν το push, εγκατέστησε το εργαλείο 'act' (https://github.com/nektos/act) και τρέξε act workflow_dispatch — τρέχει το workflow τοπικά με Docker, ίδιο περιβάλλον με το πραγματικό GitHub Actions. Δεν είναι απαραίτητο — τα προηγούμενα βήματα καλύπτουν την ουσία.

Το πιο σημαντικό βήμα είναι το #4-5: βάλε 1-2 σελίδες που ξέρεις σίγουρα ότι επιτρέπουν scraping (π.χ. δικές σου, ή κάτι δημόσιο απλό σαν Wikipedia) πριν δοκιμάσεις σε "ευαίσθητα" sites τρίτων, ώστε να επιβεβαιώσεις ότι όλο το pipeline δουλεύει σωστά χωρίς να ρισκάρεις κανένα πρόβλημα ευγένειας/robots.txt στην πρώτη δοκιμή.
